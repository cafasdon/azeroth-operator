## Compiler and transport checkpoint

`equipment_set_operation::compile` accepts a captured snapshot, its ID and `{operation: modify|delete, set_id, name?, icon?}`. Modify requires both desired fields; delete forbids them. It rejects unsupported families, missing/unusable catalogues and target IDs, invalid names/icons and captured ASCII-case-insensitive name collisions. The native executor's lookup remains authoritative for other name equivalences.

`AO-SET-1` has exactly 193 colon-separated fields and an 8192-byte ceiling. Fields 1–13 are magic, operation ID, snapshot ID, family, variant/build/interface, character/realm, kind, set ID and desired name/icon. Fields 14–22 hold expected name/icon/equipped flag, five counts and optional assigned spec. Nineteen consecutive groups of nine fields hold ignored flag, raw item ID/location, observed kind/slot/bag/item ID/GUID/lock. Text uses lower-case hex; absent fields use `-`; booleans use `0`/`1`. Numeric zero, false and absence remain distinct. Empty slot objects remain objects rather than inferred empty equipment.

The operation ID hashes every transport field with a blank ID placeholder. It binds compiler output to all captured data; it is not authentication. The Lua decoder validates ID syntax, field count, kinds, canonical numbers, bounds, conditional placeholders and observed-item consistency without executing imported text. It does not independently recompute SHA256. Future review must display and bind the exact bytes, and receipt handling must refuse already-attempted IDs. New snapshot IDs can produce new operation IDs, so this alone cannot prove semantic exactly-once execution.

The result explicitly reports `addon_execution_enabled: false`, `game_execution: false` and `live_qualified: false`. Deletion and assigned-spec context are included; external-reference repair is false. Compiler/decoder presence is not a deployed capability.
